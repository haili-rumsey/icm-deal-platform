# ICM Deal Platform — PRD

Stream Realty Partners · Industrial Capital Markets
Rev. 4.1 · Scope: ICM only · Custom build on Vercel
(Rev. 4.1: authentication changed from Entra ID SSO to email magic links — see §9)

Internal deal tracking system replacing a hand-maintained pipeline spreadsheet. Single source of truth for deals, properties, bids, companies and contacts. 12 users across Dallas and Houston.

This spec was written decision by decision. **Every field here was deliberately chosen, including the ones left out.** Deliberately out of scope: permissions/visibility rules, audit tables, document storage, SharePoint integration, marketing engagement tracking, post-closing task tracking, commission splits, sale comps. If something seems missing, ask before adding it.

---

## 1. Data model

Six entities plus join tables: Deal, Property, Company, Contact, Bid, Note. Joins: Deal Property, Deal Party, Deal Team. Plus a narrow Change Log.

### Deal

| Field | Type | Notes |
|---|---|---|
| `deal_name` | text | Convention: `Client Name-Deal Name` |
| `reapps_id` | text | Generated by REApps (accounting) at closing. Ties the record back to accounting. |
| `category` | enum | Industrial · Office · Retail · IOS · Land · Mixed |
| `deal_type` | enum | Sale · Equity · Debt · Lease (see §2) |
| `deal_subtype` | dependent enum | Sale → Investment Sale, Forward Sale, NNN, Portfolio. Equity → JV. Debt → Senior Financing. Not used for Lease. |
| `opportunity_type` | enum | Core · Core Plus · Value Add · Opportunistic · Development |
| `represented` | enum | Seller/Landlord · Buyer/Tenant · Both |
| `is_ios` | bool | IOS-desk deal (sales and leases both). Marks the **desk**, not the asset type. |
| `direct_award` | bool | Awarded without a competitive process; marketing and bid rounds skipped. |
| `stage` | enum | See §3 |
| `submarket` | lookup | Filtered by city. See §4. |
| `walt_years` + `walt_as_of` | decimal + date | Point-in-time pair |
| `referral` | user | Stream employee who sent the business |
| `closing_notes` | text | Extensions, delays, anything abnormal |
| `last_modified_at` / `_by` | auto | On every entity |

#### Dates

| Field | Meaning |
|---|---|
| `pitch_date` | Proposal delivered → BOV 2 |
| `pitch_status` | Won · Lost |
| `lost_to_company` | Competitor who won it |
| `lost_note` | Free text |
| `won_date` | Client confirms → Engaged |
| `launch_date` | First marketing email → Marketing |
| `call_for_offers_date` | Offer deadline |
| `awarded_date` | Buyer selected → Awarded |
| `dd_expiration_date` | End of due diligence |
| `close_date` | Actual close |

Dates overwrite; there is no date history. `closing_notes` explains anomalies.

#### Financials — three independent blocks

| Block | Price | Underwriting |
|---|---|---|
| BOV | low / mid / high | Year 1 cap, ULIRR, LIRR, exit cap, hold period. Overwritten on repricing. |
| OM / Guidance | `guidance_price` (**internal only**) | Same metrics, as marketed |
| Closed | `contract_price` → `closed_price` | Same metrics, as transacted |

The three blocks **never overwrite each other**. `guidance_price` is given out on request but never published — it must not appear in client-facing output.

`price_psf` is calculated (active price ÷ total SF of linked properties), never typed. `price_notes` explains retrades or credits.

#### Fee — mirrors accounting

| Field | Meaning |
|---|---|
| `total_commission` | Gross fee |
| `outside_commission` | Paid outside ICM — external co-brokers and other Stream entities |
| `outside_commission_note` | Who it went to |
| `in_house_gross` | Net to the team |
| `fee_rate` | Flat %, optional |

No per-person splits — those live in accounting software.

### Property

Standalone and persistent; accumulates transaction history across repeat trades. Joined to deals many-to-many via `deal_property`, which carries an optional `allocated_price`.

| Field | Notes |
|---|---|
| `address` / `city` / `state` / `zip` / `county` | Resolved via Google Geocoding |
| `building_designation` | Building A, Bldg 2 — participates in duplicate matching |
| `google_place_id` / `lat` / `long` | Place ID is the duplicate key |
| `submarket` | Filtered by city |
| `building_sf` / `acreage` | Roll up to deal totals |
| `occupancy_pct` + `occupancy_as_of` | Point-in-time pair |
| `tenancy` | Single · Multi |
| `building_class` | A · B · C |
| `year_built` | |
| `clear_height_ft` | |
| `configuration` | Rear-load · Front-load · Cross-dock · Shallow bay · IOS |
| `dock_doors` | |
| `office_finish_sf` | |
| `sprinkler_type` | ESFR · Wet · Dry · Dry with in-rack · None |
| `current_owner` | Auto-updates on close from the buyer side; records both partners on a JV |

**Address handling:** users do not type addresses free-form. Google Geocoding resolves the entry; the system stores the normalized address, lat/long and `place_id`. Duplicate detection runs on `place_id` + building designation. `place_id` is a **matching attribute, never the primary key** — Google reissues them. Parcel IDs are deliberately not used (county-issued, no shared format).

Suspected duplicates **warn, never block**.

### Bid

Covers bids and LOIs. Attaches to the **company**, not the contact, so the record survives a contact changing firms.

| Field | Notes |
|---|---|
| `deal` / `company` / `contact` | Company required |
| `bid_amount` / `bid_date` | |
| `bid_round` | Round 1 · Round 2 · Round 3 · Best & Final |
| `is_awarded` | Marks the winning bid — this is what identifies the buyer |
| `fell_out` / `fell_out_date` | Awarded bid that failed before closing |
| `fell_out_note` | **Required** when marking fell out. Also auto-creates a note on that company, tagged to the deal. |
| `bid_psf` | Calculated |
| `dd_period_days` / `closing_period_days` | Numeric so the matrix sorts |
| `initial_em` / `additional_em` | Earnest money at signing, and any later deposit |
| `debt_notes` / `notes` | |

When a contract falls out (a couple of times a year): mark the awarded bid `fell_out`, deal returns to Marketing, a second bid can be awarded — without erasing the first.

The bid matrix is a **generated view**, replacing a hand-built spreadsheet per deal.

### Company, Contact, Deal Party, Deal Team

- **Company** — name, **website**, type (investor, developer, owner-user, lender, brokerage; multi-select), **investment strategy** (same list as `opportunity_type`, multi-select), notes.
- **Contact** — company, title, **email**, phone, notes.
- **Deal Party** — links a deal to one or more companies and contacts on side A or side B. Handles JVs on both sides. On a sale, side B is seeded from the awarded bid and stays editable.
- **Deal Team** — the single record of who is on a deal. Each row: a Stream user, a role (producer, analyst, operations, designer, leasing), and two optional designations: **lead broker** (multiple allowed) and **lead analyst** (one). Leads are flags on rows, never separate fields on the Deal.

Every team member, lead or not, can pull a list of deals they worked on.

**Company naming standard:** companies are recorded under the **institutional owner's real name**, never the LP or LLC holding the asset. There is no parent/subsidiary hierarchy — the rollup happens at data entry. This depends on the convention being followed and belongs in team training.

**Duplicate prevention:** companies require a website (domain is the key); individuals require an email. Both **required by default with an explicit override** — "no website" / "no email" are selectable and flag the record for cleanup.

**Delete and archive:**

| Action | Who | When |
|---|---|---|
| Delete | Haili Rumsey, Seth Koschak, Matteson Hamilton | Records created in error. Permanent. |
| Archive | Any user | Contacts who left the industry, housekeeping. Reversible. |

### Change log

Deliberately narrow: **stage transitions (from, to, when, who) and record creation.** Not a full audit table. It exists solely to feed the weekly recap (§6).

## 2. Deal types

Sales are the bulk. Equity and debt are low volume but a deliberate growth area, executed in-house. Leases come from the IOS desk. All four share the same spine — stages, dates, parties, fee, notes — and differ in two places: what the sides are called, and which number is the headline.

| Deal type | Side A | Side B | Headline number | Extra fields |
|---|---|---|---|---|
| Sale | Seller | Buyer | `closed_price` | Full BOV / OM / Closed blocks |
| Equity | Sponsor | Capital Partner | `total_capitalization` | — |
| Debt | Borrower | Lender | `loan_amount` | rate, term, LTV |
| Lease | Landlord | Tenant | `total_lease_consideration` | — |

`deal_value` is a **derived field** holding whichever headline number applies, and totals straight across all four types in volume reporting. Without it, every volume report has to special-case deal type and non-sale deals fall out of the totals.

The BOV block does not display for equity, debt or lease deals.

Accounting's export uses combined labels (Seller/Landlord, Buyer/Tenant) that map onto the same two sides.

## 3. Pipeline stages

| # | Stage | Typical duration | Exit |
|---|---|---|---|
| 1 | BOV 1 — proposal in preparation | 1–2 weeks | Proposal delivered → sets `pitch_date` |
| 2 | BOV 2 — proposal delivered | 1 week – 6 months | Won, Lost, or Track |
| 3 | Engaged — packaging / OM in process | 1–2 weeks | First marketing email → sets `launch_date` |
| 4 | Marketing | 3–4 weeks | Buyer selected → sets `awarded_date` |
| 5 | Awarded — DD and PSA negotiation | ~30 days | PSA signed |
| 6 | Under contract — closing period | 5–30 days | `close_date` recorded |
| 7 | Closed | — | Terminal |
| — | **Track** — dormant | — | Revival or Dead |
| — | **Dead / Lost** | — | Terminal |

**"Awarded" always means a buyer was selected**, never that Stream won the listing. Winning the listing is `won_date` and moves the deal to Engaged.

**Track** is a pitched deal the seller elected to hold — not lost, not dead. Excluded from active pipeline totals, reported separately, reviewed periodically so stale deals move to Dead. It also answers what the team worked on in a year including deals that never reached market.

### Governing principle — the system never blocks a deal

A deal can be created at **any** stage and moved between stages **without** complete fields. Exit conditions describe what a transition means; they are not enforced gates.

Required for the initial pipeline load, for IOS deals entering as Closed, for deals reaching the team mid-flight, and for direct awards.

**Missing data is prompted for, never enforced.** Show what's incomplete; let the user proceed. Earlier-stage fields stay editable up until the deal closes — a BOV entered six months late is still worth having.

Trade-off, stated plainly: reports will have gaps, and a completeness view is more useful than validation rules. Partial data on every deal beats complete data on the half that made it in.

### Notifications

Two date-driven alerts, the only ones in scope:

- **DD expiration** — advance warning before due diligence ends
- **Close date** — advance warning ahead of a scheduled closing

Both go to the deal team. Lead time is configurable, since a 30-day DD and a 5-day closing want different windows.

### The one exception — closed deals lock

A closed deal is **read-only for everyone except Haili Rumsey, Seth Koschak and Matteson Hamilton**, who can unlock, edit and relock. The lock covers the whole record.

Reason: closed deals carry the REApps ID and the three commission figures, which originate in accounting and are reconciled against a system ICM does not control.

This is a single role distinction, **not a permissions layer**. All users still see every deal.

## 4. Geography

Three levels — **State → City → Submarket** — with submarket options filtered by the city selected. Reports filter or group on any level. Operations owns the list; **users cannot add entries**.

Cities without a submarket list carry city-level detail only. Because State is its own level, out-of-Texas deals fit without special handling.

**Dallas (14):** Denton · Lewisville · DFW Airport · South Stemmons · Dallas CBD · North Stemmons–Valwood–Metro Addison · Pinnacle–Lonestar–Turnpike · Great Southwest–Arlington · South Dallas · 287 Corridor · 121 Corridor–Frisco · McKinney–Allen · Richardson–Plano · Northeast Dallas–Garland–Mesquite

**Fort Worth (2):** North Fort Worth · South Fort Worth

**Houston (7):** North · Northwest · West · Southwest · South · Southeast · East

Compound submarkets stay combined as published. Fort Worth is a separate city from Dallas; 287 Corridor and Great Southwest–Arlington remain on the Dallas list, following the published submarket map.

## 5. Notes and attribution

Notes belong to the **Company** — relationships outlive deals.

| Field | Notes |
|---|---|
| `company` | Required. The note's home. |
| `deal` | Optional tag — also surfaces on the deal |
| `contact` | Optional |
| `author` | Whose note it is |
| `entered_by` | Who typed it. Displayed as "Seth Koschak · entered by Haili Rumsey." |
| `logged_at` | Date entered into the system, set automatically |
| `source` | Call · Meeting · Email · Tour · Roadshow · Internal |
| `body` | Editable, last-modified stamped |

Filtering on `author` gives each producer a complete view of their own notes regardless of who entered them. No confirmation loop.

## 6. Reports

| Report | Contents |
|---|---|
| Pipeline | Active deals grouped by stage. Lead analyst is the only team field shown. Track reported separately, never blended into active totals. |
| My deals | Every deal a team member worked on, lead or not |
| Submarket | Everything sold in a submarket; filterable at state, city or submarket level |
| Property | SF range, location, clear height, class, configuration. Map view. |
| Company | What they're bidding on, selling, have purchased. Filterable by investment strategy. JV partners both credited. |
| Quarterly revenue | Closed deals and fees by calendar quarter, prior-quarter and prior-year comparison, grouped by city/metro |
| Year over year | Closed volume and fees across years, by city/metro |
| IOS vs. core ICM | Closed-deal revenue split by the IOS flag |
| Dormant / Track review | Everything parked, for review and culling |
| Opportunity | By deal type, subtype, closed date range |
| Team notes | All notes by date range, author, company |
| Referral sources | Who across Stream sends ICM business, and what it became |
| BOV accuracy | BOV midpoint against closed price |
| Fee summary | Total commission, outside commission, in-house gross by period |

All reporting runs on **calendar quarters**.

### Weekly recap email

ICM walks every active deal — BOV 1 through Under Contract — in one weekly meeting. The recap sends automatically **after that meeting**, to the whole team, so anyone who missed it sees what moved.

Covers **the previous seven days plus the day it sends**. No session tracking.

Sections: stage moves (from, to, who) · new deals · awards and fell-outs · bids received · closed deals with value and fee · dead and dormant · notes logged with author.

Depends on the change log. Requires Vercel Cron and an email provider.

### Search

One global search across **deals, properties, companies and individuals**, results grouped by type.

Two behaviours matter most:
- Searching an **address** returns the property and every deal it has been part of
- Searching a **company** returns them whether buyer, seller, sponsor, lender, tenant, or a bidder who never won

Submarket is a report filter, not a search term.

### Export

Every report exports to **Excel**. PDF deferred.

## 7. Historical import

Closed deals load in bulk from accounting's existing export. The sale comps list and closed deal folders are out of scope.

| Column | Maps to |
|---|---|
| Deal Id | `reapps_id` |
| Deal Name | `deal_name` |
| Closed Date | `close_date` |
| Deal Type | `deal_type` |
| Seller / Landlord | Deal Party, side A |
| Buyer / Tenant | Deal Party, side B |
| Represented | `represented` |
| Property Address / City / State | Property |
| Brokers | Deal Team, flagged lead broker |
| SF / Acres | Property `building_sf` / `acreage` |
| Consideration | `closed_price` |
| Total Commission | `total_commission` |
| Outside Comm. | `outside_commission` |
| In-House Gross | `in_house_gross` |

Referral Type, Business Line and Division are in the export and **deliberately not imported**.

**Two consequences to design for:**

1. **Import validation must be relaxed.** A historical closed deal has no pitch date, no BOV, no bids. Normal-entry requirements cannot apply to imported rows or the file is rejected wholesale.
2. **Submarket is not in the export.** Imported deals carry city and state, appear in city-level reporting, and are absent from submarket reporting until backfilled. It cannot be derived from an address without boundary data.

**Active pipeline** is entered manually at launch — a known one-time lift.

**IOS desk deals:** the IOS desk transacts **both sales and leases**. All of it is entered or imported as **closed only**, never tracked as active pipeline, and carries `is_ios`. Import validation must accept a deal that has never held any stage but Closed. An IOS sale records the same closed-block fields as any sale; a lease records total lease consideration and the fee.

## 8. Build order

Two phases, each with milestones and an explicit definition of done. A milestone is finished when its test passes — not when the code is written. No dates: sequence is the commitment.

### Phase 1 — replace the pipeline spreadsheet

Phase 1 ends when the pipeline spreadsheet is retired. A system running alongside the spreadsheet is a second place to type.

| Milestone | Delivers | Done when |
|---|---|---|
| 1.1 Foundation | Repo, Vercel deploy, Neon database, magic-link sign-in (Resend), user administration | A Stream user signs in with their own credentials and reaches an empty app |
| 1.2 Core records | Deal, Property, Company, Contact, Deal Team, Deal Party | A multi-property deal can be created with a JV on both sides and a full team |
| 1.3 Geography and duplicates | State/city/submarket lists, Google geocoding, website and email keys | Entering an existing address surfaces the existing property instead of creating a second one |
| 1.4 Stages and money | All stages incl. Track, dates, three financial blocks, fee fields, closed-record lock | A deal runs BOV 1 → Closed, and a non-privileged user cannot edit it afterward |
| 1.5 Historical import | Bulk load of accounting's closed-deal export | The real file loads with no rejected rows, and IOS sales and leases both land as closed with the flag set |
| 1.6 Core reports | Pipeline, opportunity and property reports, Excel export, search | The weekly meeting is run off the system instead of the spreadsheet |

### Phase 2 — bids, notes and intelligence

Phase 2 ends when the recap email sends itself every week without anyone touching it.

| Milestone | Delivers | Done when |
|---|---|---|
| 2.1 Bids | Bid records, rounds, awarded and fell-out handling, generated bid matrix | A live deal's bid matrix is shared with a client straight from the system |
| 2.2 Notes | Company notes, author and entered-by, optional deal tag | A note logged on someone's behalf appears in their own notes view correctly attributed |
| 2.3 Plumbing | Change log, Vercel Cron, email provider | A scheduled job fires on time and delivers mail to the team |
| 2.4 Weekly recap | The post-meeting email, all seven sections | Someone who missed the meeting can reconstruct it from the email alone |
| 2.5 Alerts | DD expiration and close date notifications | A deal team is warned ahead of a real DD expiration |
| 2.6 Remaining reports | Company, submarket, referral, BOV accuracy, fee, quarterly and year-over-year | A quarter's revenue reporting is produced without opening Excel first |

### Later

Investor profiles and targeting · submarket backfill on historical deals · PDF export

**Two sequencing notes.** The historical import sits at 1.5, before reports — loading history is the step that quietly kills rollouts, and a system that opens with real closed deals beats an empty one competing with a spreadsheet that works. And 2.3 is deliberately its own milestone: cron and outbound email are infrastructure the recap cannot exist without, and burying them inside a feature is how they get discovered late.

## 9. Build and hosting

Custom build, developed in-house.

| Layer | Choice | Notes |
|---|---|---|
| Application | Next.js on Vercel | Serverless — nothing runs continuously |
| Database | Neon Postgres | Vercel's native integration. Managed backups with PITR are a setting, not a build task. |
| Source control | Private GitHub repo | Stream-owned account, not personal. This is the continuity plan. |
| Authentication | Email magic links (Auth.js email provider via Resend) | No passwords, no dependency on Stream IT. Replaces Entra ID SSO — see Authentication below |
| Scheduled jobs | Vercel Cron | Required for the weekly recap |
| Outbound email | Resend | Sign-in links from 1.1; also required for the recap |
| Geocoding | Google Geocoding API | Address normalization and the `place_id` duplicate key |

### Authentication

**Changed from Rev. 4:** Microsoft Entra ID SSO is replaced by email magic links, to avoid a dependency on Stream IT. Auth stays in an isolated layer so Entra ID can be swapped in later without touching the rest of the app.

- **Sign-in:** user enters their email, receives a one-time link, clicks it.
- Restricted to **@streamrealty.com** addresses, and to people an admin has added (ICM team only).
- Magic links are **single-use** and **expire after 15 minutes**.
- Sessions last **7 days**, then the user signs in again.

**User administration** — accessible only to the same three users who can delete records and unlock closed deals (Haili Rumsey, Seth Koschak, Matteson Hamilton):

- Add a user and see everyone who currently has access
- Deactivate a user, which must **immediately** (a) stop any new sign-in link being issued to them and (b) terminate their active sessions — not just block future logins

This is the same single role distinction as the closed-deal lock, not a permissions layer.

**Backups** are handled by Neon, but check retention against the plan tier — free tiers keep very little history. Budget for paid on both.

**Two risks worth naming:**

- **Tell Stream IT before building, not after.** This holds client contacts, deal financials, bid terms and fee data. Infrastructure IT doesn't know about is how a system gets pulled six months after the team depends on it. Involving them early may hand off hosting, SSO and backups entirely.
- **The continuity risk is the system depending on one person.** A Stream-owned repo, a managed database and documented environment variables are what make it survivable — decisions made at setup or not at all.
